# Adding a Minecraft Version

AutoConnect keeps the release matrix in `gradle/autoconnect-metadata.json`. Fabric projects are generated by Stonecutter from that metadata; Forge, NeoForge, and Quilt also need a loader version project directory.

## 1. Update the metadata matrix

Add the new Minecraft target under each loader in `gradle/autoconnect-metadata.json`.

- Fabric and Quilt targets need `minecraftDependency`, `minecraftLabel`, `minecraftVersions`, `modMenu`, `modMenuDependency`, `clothConfig`, and `clothConfigDependency`.
- Forge targets need `minecraftLabel`, `minecraftVersions`, `forgeVersion`, `minecraftRange`, and `forgeRange`.
- NeoForge targets need `minecraftLabel`, `minecraftVersions`, `neoForgeVersion`, `minecraftRange`, and `neoForgeRange`.

Use `minecraftLabel` for the artifact suffix. If one build supports a range, keep the key on the compiled version and put the full supported list in `minecraftVersions`.

## 2. Add loader project directories

Fabric projects are created from `settings.gradle`, so no `versions/` directory should be committed manually.

For the other loaders, add one directory per new target:

```text
forge/<minecraft-version>/build.gradle
neoforge/<minecraft-version>/build.gradle
quilt/<minecraft-version>/build.gradle
```

Each file usually only applies the shared loader Gradle file:

```groovy
apply from: "../../forge.gradle"
```

Adjust the relative path for NeoForge and Quilt:

```groovy
apply from: "../../neoforge.gradle"
apply from: "../../quilt.gradle"
```

## 3. Refresh generated README content

Run:

```sh
gradle updateReadmeGeneratedContent
```

This updates the compatibility list and artifact examples from the metadata.

## 4. Build and inspect the matrix

Run the version checks before publishing:

```sh
gradle printMinecraftVersionMatrix
gradle checkReadmeGeneratedContent checkAllMinecraftVersions :unit-tests:test
gradle preparePublishArtifacts
python .github/actions/publish/validate_publish_artifacts.py
```

For Forge, NeoForge, and Quilt, also build the new subprojects directly:

```sh
gradle :forge-<minecraft-version>:build
gradle :neoforge-<minecraft-version>:build
gradle :quilt-<minecraft-version>:build
```

## 5. Check publish metadata

The `Publish Dry Run` GitHub Actions workflow builds the upload jars and validates Modrinth and CurseForge metadata without using tokens or uploading files.

Run it before the real `Publish` workflow when a Minecraft target, loader version, Java version, platform project id, or release artifact naming changes.
